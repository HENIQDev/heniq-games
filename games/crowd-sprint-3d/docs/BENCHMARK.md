# ベンチマークの記録と手順（CROWD SPRINT 3D 版）

> **方針（2026-11-22 更新）**：iPhone 実機の検証は行わない（リリース後にオーナーが確認）。実機の項目は**未確認**として記録。Mac のブラウザでの検証は、末尾の「追記」にまとめた。

**結論（正直に）：iPhone 実機の 60fps は、まだ確認できていない。** 下の Mac の数値も、計測環境が他のアプリで高負荷だったため、FPS と GPU 時間は無効（参考外）。**有効なのは、構造の数値と、JS の CPU 時間だけ。**

## 2026-11-22 の計測（Mac・Chrome。iPhone ではない）
### 無効だったもの（環境の問題）
計測中の Mac は、Blender などが動いていて**高負荷**（ロードアベレージ 22〜80、WindowServer も高い）。ゲームとは無関係な、**何も描かない WebGL の空のループ**でも、FPS 24〜50・GPU 時間 3〜35ms になった（ゲーム内のベンチは、この確認を自動で行い、警告を出す）。そのため、ゲームの結果（FPS 32〜44・GPU 42〜55ms）は、**ゲームの重さを表していない**と判断し、合否には使わない。
| 試したこと | 結果 |
|---|---|
| 解像度 0.3／0.5／1.0 で GPU 時間を比較 | ほぼ同じ（45／20〜42／52ms）→ ピクセルの負荷ではなく、環境のノイズ |
| 描画する要素を絞る（`?only=…`）| 何も描かない場合でも 20ms → 環境の待ち時間が支配的 |
| ヘッドレス Chrome と、実際のウィンドウの Chrome | どちらも同様 |
| 空の WebGL ループ（ベースライン） | 24.4fps・GPU 35.6ms（高負荷時）／60fps・2.8ms（少し空いた時） |

| 入力遅延 | 未計測（ボットの入力にはイベントがない。実機で `?perf=1` を見ながら操作して測る） |

## 見立て（計測ではなく、設計からの推測。実機で確認するまで「未達成」）
8〜9 万三角形・描画コール 6・テクスチャなし・フラグメントは軽量（ランバートとフォグのみ）・アンチエイリアスなし・解像度の動的調整、という構成は、近年の iPhone（A14 以降）の GPU の能力に対して余裕のある範囲のはず。ただし、頂点シェーダーでの関節の計算（約 25 万頂点）と発熱は、実機で確かめる必要がある。

## 実機の測り方（**承認が必要**：実機の接続・操作・計測）
1. Mac で `python3 tools/build.py && python3 tools/serve.py --lan` を起動（同じ Wi-Fi の端末だけ。終わったら Ctrl+C）。
2. iPhone の Safari で `http://<Mac の IP>:8790/crowd-sprint-3d/?bench=1&loop=7`（約 3 分。画面に触れない。最後に結果の JSON が表示される。スクリーンショットで共有）。
3. 遊びながらの確認：`…/crowd-sprint-3d/?perf=1`（FPS・CPU・GPU・解像度・描画コール・入力→フレームの時間を画面に表示）。DASH・JUMP・なぞりの同時操作（3 本指に近い操作）も確認。
4. GPU 時間と発熱：Mac の Safari の Web インスペクタから実機に接続して Timelines（Graphics・CPU）を記録、または Xcode の Instruments（Metal System Trace・Thermal State・Allocations）。
5. 本体の温度と手触りを申告。
`&scale=0.75` で解像度を固定すると、解像度ごとの比較ができる（指定がなければ自動で調整）。
### 合格の基準（目標）
iPhone 実機（A14 以降が目安。機種はあなたが決める）で、800 人表示のレース全体で **平均 58fps 以上・p95 のフレーム間隔 20ms 以下・3 分連続でも FPS の低下 10% 以内**。

## 計測の道具
- ゲーム内：`?perf=1`（FPS・CPU・GPU・解像度・描画コール・三角形・LOD 別の数・入力遅延）、`?bench=1&loop=N`（ベンチ。ベースラインの確認つき）、`?scale=…`。
- `tools/cdp.py`：Chrome を実時間で動かして結果を取る（`--window` で実際のウィンドウ。`--virtual-time-budget` は時間を早送りするので、FPS には使えない）。
- テスト：描画コール・三角形・GPU バッファ・全員が 3D・CPU 時間の上限（回帰の検出。実機の合否ではない）。

## 追記（2026-11-22）：実機検証は行わない方針。Mac のブラウザでの検証の記録
ユーザーの方針：**iPhone 実機の検証は不要**（リリース後にご自身で iPhone でプレイして確認）。実機の FPS・発熱・入力遅延などは、**未確認として記録**する。代わりに、Mac のブラウザで次を徹底した。実機の測り方（上）は、リリース後の参考として残す（LAN での実機テスト環境の構築は行わない）。

### 1. 性能計測（複数回・無効な測定を除外）— `tools/perf_runs.py`
各回で、Mac の負荷と、何も描かない WebGL のベースライン（ゲーム内のベンチが測る）を確認し、基準外の回は無効として採用しない。
| 項目 | 結果 |
|---|---|
| 試行 | 6 回（負荷 4.7〜14）＋ 8 回（負荷 3.9〜10.5）。基準：ベースラインの空のクリアが 1.5ms 未満・フレーム間隔 17.5ms 未満・ロードアベレージがコア数の 0.8 倍未満 |
| 有効な回 | **1 回／14 回**（3 回に満たないため、**FPS・GPU 時間は採用しない**） |
| 参考（無効）の傾向 | FPS 約 45〜53、GPU 時間 約 26〜44ms（何も描かない場合でも 約 14〜16ms。HUD を外しても変わらず）。**この環境（Chrome の ANGLE/Metal・他のアプリと GPU を共有）では、GPU 時間の固定の遅れが大きく、ゲームの重さを表していないと判断** |
| 切り分け | 解像度（0.3／0.5／1.0）・描画要素（`only=`）・HUD の有無のどれを変えても、傾向が変わらない → ゲームの負荷ではなく、計測環境の固定の遅れ |

**採用する数値は、環境に左右されないものだけ**：描画コール 6／約 8.4〜9.6 万三角形／GPU バッファ 3.2MB／JS の CPU 時間 平均 約 1ms（最悪 約 1.5〜3.6ms。複数回の測定で 0.8〜1.3ms）。

### 2. メモリ・長時間動作（ソーク）
レースを描画つきで連続して走らせ、1 レースごとに GC を行ってからメモリなどを記録（`?soak=N`）。
| 回数 | 結果 |
|---|---|
| 80 レース（約 10.8 万フレーム）| JS ヒープ 4.3MB → 5.8MB（最大 5.8MB）。**1 レースあたりの増加 0.005MB（実質ゼロ）**。DOM 26→25 要素。GL エラー 0。GPU バッファ量は一定。全レースでゴール |
| 14 レース（自動テスト）| 同様。テストの基準：増加 0.3MB/レース未満・ヒープ最大 60MB 未満・DOM の増減 2 以内・GPU バッファ一定・GL エラー 0 |

### 3. 操作（実際のブラウザイベント）— `tests/test_input.py`
Chrome に、本物のキーとタッチのイベントを送って確認（`tools/cdp.py`）。
- キーボード：← → で左右に動く／Shift 長押しでダッシュ（速度が上がりスタミナが減り、離すと止まる）／Space でジャンプ。
- マルチタッチ：1 本の指でなぞって移動／同時に 2 本目で DASH ボタン／さらに 3 本目で JUMP ボタン（3 本の指の同時操作）／指を離すとダッシュが止まる。

### 4. 転倒・復帰・追い抜き（決まった状況の再現）— `?scenario=…`
- 転んだ人に突っ込む：つまずく（約 1.2 秒）→ 約 1.4 秒後に走りに戻る。
- 転んだ人をジャンプで越える：つまずかない。
- 遅い人にぶつかる：よろける（ふらつき +1）・一時的に減速・転ばない。
- 転倒の連鎖：5 つの種のすべてで、他の人が連鎖で転ぶ。同時に転ぶ人は上限 45 人以内。転んだまま固まる人はいない。
- NPC の状態：転びかけ → 転倒 → 起き上がり → 走る の順に進む。姿勢（前傾・横倒れ・腕）が状態ごとに違う。
- 追い抜き：800 位から始まり、追い抜くたびに順位が上がる（例：727 人を追い抜いて 81 位）。
- 見た目の確認：転んだ人は**横向きに倒れ、足元に赤い危険ゾーンの輪**が出る（最初は前向きに倒れて、後ろ上のカメラからほとんど見えなかったため修正）。

### 5. 画面サイズ別のレイアウト — `tests/test_input.py`（ViewportTest）
iPhone SE 以前（320×568）・SE（375×667）・15（393×852）・Pro Max（430×932）・iPhone 横（852×393）・iPad 縦横・ノート PC（1440×900）・デスクトップ（1920×1080）・ウルトラワイド（2560×1080）で、画面が はみ出さない／縦横比が 2:3 のまま／スクロールが出ない／3D と HUD の Canvas が重なる／3D の解像度が適切／START ボタンとミュートが画面内、を確認。ストアと詳細ページは、幅 375・1280 で横はみ出しなしを確認済み。
