## 技術
素の HTML／CSS／ES モジュール／Canvas 2D。ビルドは Python 3 標準機能のみ（HP と同じ流儀。Node 不要）。3D や物理は、必要なゲームだけが個別に取り込む（基盤には入れない）。

## 共通基盤（platform/core）
- `startGame({ meta, width, height, scoreOrder, formatScore, create(env) })`。`create` が返すゲームは `update(dt)`・`draw(g)`・`score`・`isOver`（任意で `hud()`）だけを持つ。
- ランタイムが担当：固定刻み（1/60 秒）のループ、画面の拡縮（DPR 対応）、開始／ゲームオーバー／リトライの画面、操作説明、自己ベスト（表示用のスコアだけを localStorage に保存。失敗しても動く）、タブが隠れたら一時停止。
- 入力は共通の形に変換：キーボード（矢印・WASD・Space/Enter）とポインター（マウス・タッチ）。
- 乱数は種つき（`rng.js`）。1 プレイごとに種を持つので、将来のリプレイ検証に使える。
- 必要な機能だけ使う：`features`（`game.json`）で宣言。ランキングを使わないゲームには何も読み込まない。
- 自己テスト（`?selftest=1`）：起動→開始→操作→ゲームオーバー→リトライを自動で通す。全ゲーム共通。
- CSP：`script-src 'self'`・インラインのスクリプトとスタイルなし・外部通信なし。

## ランキングの設計（M3。承認された方針を反映）
**原則：信頼できるのはサーバーだけ。ブラウザの値は何も信用しない。**
- **秘密鍵はブラウザに置かない。** localStorage にも置かない。HMAC の鍵は Worker の secret にだけある。
- **プレイヤー識別**：サーバーが署名つきの識別子を HttpOnly・Secure・SameSite の Cookie で発行する（JavaScript から読めない）。ブラウザは識別子の中身を知らない。ニックネームは表示用の文字列で、識別には使わない。
- **スコアの提出**：①ゲーム開始時に `POST /start` → サーバーが開始時刻・ゲーム ID・種（seed）・ナンスを入れたトークンを HMAC で署名して返す ②終了時に `POST /submit`（トークン＋スコア＋任意の操作記録）→ サーバーが署名・期限・一度きりの使用・経過時間とスコアの整合・ゲームごとの上限を検査 → 自己ベストを更新したときだけ書き込む。
- **決定性のあるゲーム**（種で全部再現できるもの）は、操作記録をサーバーで再生して検証できる。それ以外は妥当性の検査と回数制限までで、完全な不正防止はできない（楽しむためのランキングと割り切る。UI にもそう扱う）。
- **同一オリジン**：Safari などはサードパーティ Cookie を制限するので、API は `heniq-games.pages.dev/api/*`（Pages Functions＋D1）に置く案を第一候補にする（無料枠は Workers と共通）。別の Worker にする案との比較は M3 の直前に決める（要承認）。
- **停止しても遊べる**：ランキングは完全に任意の別機能。通信の失敗・タイムアウト（短く固定）・429・無料枠の超過は、すべて黙って「ランキングに接続できません」の小さな表示にして、ゲーム本体は影響を受けない。起動時にランキングを待たない。ランキングのコードは動的に読み込む。
- **プライバシー**：IP・メール・本名は保存しない。NG ワード検査・通報・古いデータの整理は飛び石の設計を参考にする（コードは共有しない）。
- **データ**：`players`・`best_scores(game_id, board_key, player_id, score, …)`・`boards`。`board_key` は `all` と `2026-W47`（週間・日本時間）。全体ランキングは作らないが、`game_id` と `score.order` があるので後から足せる。

## 無料運用
Pages（静的、無料）＋ Pages Functions／Workers＋D1（無料枠。Cron なし）＋ GitHub。数値の上限は M3 の前に公式資料で再確認する。超えるとランキングだけが止まる（課金なし）。

## 100 本以上に向けて
